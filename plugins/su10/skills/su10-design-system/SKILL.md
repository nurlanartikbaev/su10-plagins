# Дизайн-система SU10 — как собирать макеты

> **Версия 4.36.0 · 18.11.2026 · обновил Nurla.** Что менялось — в разделе «Версии» в конце.

Иконки: **SU10 Icon Pack** (до переименования — `Test Icon Pack`), fileKey `SY8WplV9pQCSFLWfD1pTcQ`.

## Порядок работы

В этом файле правила, которые действуют всегда. Остальное лежит в справочниках `references/`. Открывай только те, что нужны задаче: так сборка тратит меньше контекста.

| Шаг | Что сделать | Справочник |
|---|---|---|
| 1. Спека | Разобрать требования, собрать вопросы, составить карту экранов | `spec-to-layout.md` |
| 2. Сборка | Выбрать компоненты, взять ключи, собрать экран | маршрут в разделе «Что читать под задачу» |
| 3. Проверка макета | Прогнать аудит, посмотреть снимок в обеих темах | `audit.md` |
| 4. Проверка состояний | Заполнить матрицу, прогнать скрипт, записать пропуски | `states-audit.md` |
| 5. Сверка с кодом | Определить, что фронт соберёт как есть, а что нужно обсудить | `code-parity.md` |
| 6. Хэндофф | Запустить критиков, собрать доску из апрувнутых экранов и секцию ревью | `handoff.md`, §0, `team-workflow.md` |

Шаги начинают с того, о чём просят. Если экраны идут на доску для разработки, открой `handoff.md` до сборки: сетку и имена закладывают сразу.

## Что читать под задачу

Открывай только нужное. `keys.md` не читай целиком: ищи строку компонента по имени.

| Задача | Что открыть |
|---|---|
| Вопрос про токен или цвет | `color.md`, нужная таблица |
| Экран или форма | рецепт из `recipes.md`, файл компонента из `components/`, строки из `keys.md`, `keys-tokens.md`, пролог из `plugin-api.md` |
| Таблица | `data-tables.md`, `table-scripts.md`, пролог из `plugin-api.md` |
| Скрипт упал | `plugin-api-traps.md`, таблица симптомов |
| Экраны JUZ40 | дополнительно `juz40.md` |
| Проверка макета | `audit.md`, `states-audit.md`, `accessibility.md` |
| Передача в разработку | `handoff.md`, §0, затем `team-workflow.md` |
| Новый компонент | `new-component.md` |

## Железные правила

1. **Сначала компоненты SU10.** Всё, что есть в системе, берётся только из неё. Легаси-библиотеки `JUZ40 UI-Kit` и `Juz40 Landing` (это их настоящие имена, не путать с переименованной системой) **в продуктовых макетах можно использовать при надобности** — готовым блоком из старого макета, когда такого блока в SU10 нет. Есть в SU10 — старый блок не берут. **В самом DS-файле** легаси не подключают и паттерны оттуда не копируют. Страница `sandbox` — не референс, там живёт старый кит (607 чужих инстансов, чистке не подлежат). Чего нет ни в SU10, ни в старом ките — см. «Чего в системе нет».
   **Состояние на 22.09:** вне `sandbox` чужих компонентов в файле не осталось. Единственное исключение — мок-обвес устройства на MobileHeader и MobileTabbar (24 инстанса статус-бара из стороннего iOS-кита): это рамка устройства вокруг примера, трогать не надо.
2. **Не детачить инстансы.** Нужного состояния нет: действуй по правилу 17. Нужного элемента нет совсем: раздел «Чего в системе нет».
3. **Никаких сырых значений.** Цвет, отступ, радиус, размер — только переменные. Текст — только текстовыми стилями.
4. **Платформа — мода.** Мода переключает токены компонентов, а экраны телефона и десктопа собирают отдельными фреймами. Коллекция `Platform` (Mobile / Desktop) ставится на корневой фрейм экрана. Тема — коллекция `Theme` (Light / Dark). Один макет, две моды.
5. **Иконки — только стиль Outline** из пака. Linear красится обводкой и теряет цвет при подмене. Исключение — те иконки, которых в Outline в паке просто нет: `Check` и семейство `Sort`; они остаются Linear, пока их не нарисуют.
   **Другой стиль иконки разрешён только здесь:** «⋯» в кнопках, самолётик отправки в поле, цветные логотипы соцсетей, сердце выбранного `Favorite`, замок. Условия и ключи: `icons.md`, раздел «Исключения из Outline».
   **Исключения чата** (`ChatButton`, выбранный таб, кнопки чата, название JuzAI): `references/juz40.md`, раздел «JuzAI и ChatButton».
6. **В одной строке лейаута — один размер контролов.** Таблица высот ниже.
7. **Один компонент — один паспорт.** Сводных док на несколько компонентов не делаем.
8. **Чужую работу дублируй перед правкой.** Меняешь существующий компонент или паспорт не по прямой просьбе владельца — делай копию рядом и показывай её, оригинал не трогай.
9. **Заголовок и подзаголовок — всегда компонент, а не текстовый слой.** Заголовок экрана или крупного блока — `Heading`, заголовок секции внутри блока — `Subheading`. Текстовый слой с правильным стилем выглядит так же, но теряет всё остальное: собственные отступы, место под счётчик и действие, `Show Subtitle` и `Show Divider`, поведение при смене моды `Platform`. Через несколько экранов самодельные заголовки расходятся между собой на 2–4 px и по вертикальному ритму — на глаз это ловится, только когда экраны положат рядом. Единственное исключение — паспорта компонентов: там свои `DocHeading` и `DocSubheading`.
10. **Разделитель — только между строками списка, у последней строки его нет.** Список из `ListItem` в шторке, в `Island`, в слоте `Accordion`, в `Dialog`, в витрине паспорта: у последней строки `Show Divider = false`. Строку списка определяет следующий сосед: если за ней нет другой `ListItem` (конец контейнера, `Alert`, кнопка, другой блок) — линию выключить. То же для отдельных `Divider` между `ProfileItem` и любыми блоками: `Divider` стоит только **между** двумя элементами, ни первым, ни последним в контейнере. Линия под последней строкой упирается в край карточки или подвал и выглядит как обрезанный список. При сборке строк в цикле выключай линию у последней сразу, а не «потом проверю»:
   ```js
   rows.forEach((r, i) => setProps(r, { 'Show Divider': i < rows.length - 1 }));
   ```
   Проверка перед сдачей: счётчик `lastDivider` в `audit.md`.

11. **Новый компонент — только когда существующие не закрывают задачу.** Перед тем как
    создавать компонент (даже по прямой просьбе «собери компоненты для …»), разложи задачу
    на то, что в системе уже есть, и покажи это владельцу. Заводить новое можно, только если
    ничего не подошло, и тогда в отчёте сказано, что именно не подошло и почему. Порядок
    проверки — первый пункт раздела «Если добавляешь компонент в систему».

12. **Без тавтологий: один факт — в одном месте экрана.** Перед сдачей пройди по экрану и
    вычеркни всё, что уже видно рядом:
    - выбранная неделя подсвечена в навигации — значит, её номер не дублируют ни в
      подзаголовке шапки страницы, ни в заголовке блока справа;
    - процент уже написан в строке — шапка блока говорит другое (что осталось, что делать);
    - заголовок аккордеона «Итог месяца» — подзаголовок не повторяет «итог месяца»;
    - кнопка дублирует плашку, которая ведёт туда же (рейтинг → аналитика), — оставь
      что-то одно.

    Каждый повтор отнимает место и заставляет читать одно и то же дважды. Если без
    подзаголовка блок пустеет — его выключают, а не заполняют пересказом.

13. **В макете компоненты стоят в покое: `State=Rest`.** `Pressed`, `Hover`, `Focused` — это мгновение взаимодействия, разработчик сверстает их как постоянный вид. Другое состояние ставят, только если экран показывает именно этот момент: поле в фокусе, пока вводят запрос; строка под курсором в сценарии наведения. `Signal` выбирают по смыслу действия: `Success` — только у действия про успех. Кнопка-иконка без смысла сигнала — `Signal=Info`.
    Не берут вариант «потому что так выглядит»: Tertiary в покое прозрачная, и это и есть её вид. Нужна видимая плашка — берут `Weight=Secondary`, а не `State=Pressed`. Иконку внутри кнопки не перекрашивают поверх: неверный цвет иконки значит, что выбран неверный вариант. Подменённая иконка (`Icon` / `Left Icon`) сама берёт цвет кнопки — проверено на свежих инстансах. **Но дефолтную иконку в свойство повторно не передают**: если записать в `Left Icon` ту же иконку, что стоит по умолчанию (`Plus` `1505:5044`), слетает цвет, заданный в мастере, и вектор берёт цвет из пака (19.10 плюс у «Добавить курс» стал бледным). Нужна иконка по умолчанию — ставят только `Show Left Icon=true`. После любой подмены проверяют, что заливка вектора привязана к `icon/*`, а не к переменной пака.

14. **Текст никогда не прилипает к обводке — между ними всегда воздух.** Касается любой
    границы: рамка карточки и баннера, кольцо прогресса, обводка поля, бейдж, контур иконки-плитки.
    Минимум — `Space-4` по каждой стороне до внутреннего края линии, в круге — до окружности
    отверстия (углы текстового блока тоже внутри). Внутри компонента воздух заложен мастером —
    его не ужимают; правило про собственные фреймы макета: кольца, плашки, ячейки, подписи
    поверх графиков.
    **Объём текста продумывают до сборки, а не по факту.** Перед тем как задать размер
    контейнера, прикинь самый длинный реальный вариант: «1:40 из 3:00», а не «78»; «Вычислительная
    техника · КБТУ», а не «ЕНУ»; четырёхзначное число, перевод на казахский (он длиннее русского
    на 20–30 %). Не помещается — сначала сокращают формулировку («из 3 ч»), затем берут стиль на
    ступень меньше (но не мельче 10 px), и только потом меняют геометрию. Масштабировать текст
    `rescale` вместе с контейнером нельзя — так получается 7,4 px без текстового стиля.
    Проверка перед сдачей: `(ширина отверстия − ширина текста) / 2 ≥ 4`, а для круга
    `радиус − hypot(w/2, h/2) ≥ 0`.

15. **Текст — минимум слов без потери смысла, по принципам ASD-STE100.** Касается всех строк
    макета: заголовков, кнопок, подсказок, ошибок, пустых состояний.
    - Удали слово и проверь: смысл и действие не изменились — слово лишнее.
    - Один объект — один термин на всех экранах. Синонимы не используют.
    - Действие — глагол, а не отглагольное существительное: «Оплатить», а не «Произвести оплату».
    - Инструкция — повелительное наклонение, одно действие в предложении, до 20 слов.
      Описание — до 25 слов. Это верхний предел, а не цель.
    - Активный залог, простые общеупотребимые слова, без канцелярита и цепочек из существительных.
    - **Без точки в конце строки** (решение владельца 18.11): после последнего предложения точку не ставят, между предложениями точка остаётся: «Файл больше 10 МБ. Выберите файл меньше». Вопросительный знак остаётся. Перед сдачей ищут по всем текстам строки, которые кончаются точкой.
    - **К пользователю — только на «вы»** (решение владельца 03.11): «Пройдите», «ваш», «вы здесь», а не «Пройди», «твой», «ты здесь». По-казахски так же — на «сіз»: «картаңызды», а не «картаңды». Текст с прода на «ты» при переносе в макет переписывают. Перед сдачей ищут по всем текстам файла: ты, тебя, тебе, твой, глаголы на -ешь и -ишь, повелительное без -те.
    - Не удаляют: числа и лимиты, условие, причину ошибки, следующий шаг, предлоги и союзы, без
      которых фраза становится телеграммой.
    - **Без длинного тире «—»** (решение владельца 10.11): в текстах экранов и в заметках доски.
      С ним строка читается как написанная ИИ. Части фразы связывают союзом («если», «чтобы»,
      «и») или делят на два предложения. Тире в диапазонах («9:00–10:00») остаётся. Подписи
      доски из регламента (`<Раздел> — сценарии для разработки`) не трогают.
    - **Русский текст проверяют отдельно** (решение владельца 10.11): сокращённая русская фраза
      быстро теряет смысл. Пишут, как человек сказал бы собеседнику, и читают строку вслух.
      Условие через «если», а не через тире. В каждом предложении глагол и объект: «Если не
      придете без причины», а не «Пропустите без причины» (что пропустите?). С казахского не
      переводят дословно: сначала смысл, потом русская фраза. Вопрос с ответом часто проще
      условия: «Не сможете прийти? Отмените запись».

    | Было | Стало |
    |---|---|
    | Для того чтобы продолжить, необходимо заполнить все обязательные поля | Заполните обязательные поля |
    | В данный момент у вас отсутствуют уведомления | Уведомлений нет |
    | Ошибка загрузки *(пересокращено: нет причины и шага)* | Файл больше 10 МБ. Выберите файл меньше |
    | Пропустите без причины — записаться снова нельзя *(тире, нет объекта)* | Если не придете без причины, записаться снова не получится |
    | Не сможете подключиться — отмените запись минимум за 24 часа *(тире)* | Не сможете прийти? Отмените запись за 24 часа до начала |
    | Консультация успешно забронирована *(«успешно» лишнее)* | Вы записались на консультацию |

    Проверка перед сдачей: прочитай каждую строку и вычеркни всё, без чего пользователь поймёт,
    что произошло и что делать дальше.

16. **Иконки в одном ряду: один размер, один шаг, одна ось** (решение владельца 05.11). Касается любого ряда иконок и кнопок-иконок, вместе с крестиком из компонента. Шаг берут у компонента, в который ставят, а не на глаз. Подменённая иконка может потерять привязку размера: проверь её после подмены. Перед сдачей ряд меряют скриптом из `references/audit.md`, §2б, и смотрят снимком. Расхождение идёт из мастера — чини мастер, а не каждый экран.

17. **Фронт верстает по дизайн-системе: в ходе задачи новых состояний компонентам не придумывают** (решение владельца 06.11). У разработки есть код каждого компонента SU10 ровно с теми вариантами и свойствами, что в мастере. Всё, чего в мастере нет, фронт сверстает костылём или вернёт на доработку.
    Запрещено в продуктовом макете:
    - брать вариант не по назначению, «потому что похоже»: `Text Button` `Variant=Link` как выбранное или открытое состояние, `State=Pressed` как постоянный вид;
    - класть свой фрейм или кнопку поверх строки компонента: корзина поверх `SingleSelectItem`, красная подложка свайпа под строкой;
    - собирать «строку» из двух компонентов рядом (`ListItem` + `Button`), если в системе такой строки нет;
    - перекрашивать, переставлять и перенастраивать слои внутри инстанса: цвет иконки, шрифт и стиль текста, отступы, выравнивание, скрытие служебных слоёв;
    - использовать компонент вне его роли: `Dropdown` поля как самостоятельное меню.

    Если задачу без этого не решить, работу не продолжают молча, а **предлагают изменение компонента** и пишут точно:
    - какой компонент (имя набора и страница в SU10);
    - что добавить: новое значение варианта, булево свойство, слот, токен — с именем;
    - зачем: какой сценарий без этого не собрать, на каких экранах;
    - что временно стоит в макете вместо этого. Временное решение подписывают «Нужно в SU10: …» прямо на макете.

    В каждом отчёте — отдельный блок «Предложения к компонентам», даже если он пустой. Сам мастер меняют только после согласия владельца (правило 8).
    Проверка перед сдачей: скрипт из `references/code-parity.md`, §1, ищет в инстансах переопределения `fills`, `strokes`, `fontName`, `textStyleId`, `padding*`, `itemSpacing`, `textAlignHorizontal`, `visible` на внутренних слоях и варианты `State≠Rest`. Каждое найденное — либо убрано, либо стоит в «Предложениях к компонентам».

### Отступы `Space-*`

`0 1 2 4 6 8 12 16 20 24 32 40 48 64 80 96 128`

- внутри контрола — 4…12
- между контролами в группе — 8…16
- между блоками — 24…48
- поля оверлея — 16
- поля страницы — 24 на Mobile и на Desktop
- у `Island` своих полей нет — их приносит содержимое

12 колонок по 94, поля 24, промежуток 24 на ширине 1440. Ширины блоков и правила: `recipes.md`, раздел «Сетка десктопа».

### Радиусы `radius/border-radius-*`

`100`=4 · `150`=6 · `200`=8 · `300`=12 · `400`=16 · `500`=20 · `600`=24 · `rounded`

**Правило вложенности:** внешний радиус = внутренний + отступ между ними. Дорожка сегментов S: 4 + 2 = 6.

### Высоты строки `height-*` (Mobile / Desktop)

`100` 12/14 · `200` 14 · `300` 16 · `400` 18 · `500` 18/20 · `600` 20/22 · `650` 24 · `700` 24/28 · `800` 28/32 · `900` 32/38 · `1000` 36/40

`650` и `1000` — не line-height, а высоты строк в оверлее: `650` (плоские 24) — заголовок группы в меню и в Dropdown, `1000` (36/40) — кликабельная строка меню и бюджет высоты для слота `DesktopHeader`.

**Иконка рядом с текстом** берёт `height`-токен той же ступени, что line-height текста: Body 1 → `600`, Body 2 → `500`, Body 3 → `400`, Body 4 → `300`.

## Чек-лист перед сдачей макета

Половина пунктов проверяется скриптом — **`references/audit.md`**, он read-only и возвращает
находки с id слоёв. Порядок сдачи: прогнать скрипт → починить → снять скриншот и посмотреть
глазами. Третий шаг не отменяется вторым: у скрипта есть слепые зоны, они перечислены там же.

| Пункт | Кто проверяет |
|---|---|
| Все элементы — инстансы, детачей нет | скрипт (`detachLookalike`) + глаза |
| Цвета, отступы, радиусы, размеры — на переменных, и именно на семантических, а не на примитивах | скрипт (`rawFill`, `primitiveFill`, `rawRadius`) |
| Текст на стилях, ручного размера шрифта нет | скрипт (`textNoStyle`, `foreignFont`) |
| Иконки стиля Outline, цвет привязан к токену и совпадает с цветом своей подписи | скрипт ловит двойной слой цвета (`twoLayerIcon`), остальное — глаза |
| Primary-кнопка на экране одна | скрипт (`primaryButtons`) |
| Компоненты в `State=Rest` (кроме экрана, который показывает момент взаимодействия), `Signal` по смыслу, иконки не перекрашены поверх | глаза, железное правило 13 |
| Ни один горизонтальный ряд не вылезает за контейнер (`сумма детей + gap ≤ ширина − поля`); где не влезало — дети на `FILL`, а не торчат за краем | скрипт (`rowOverflow`) |
| В строке лейаута один размер контролов | глаза |
| Нет тавтологий: факт, видный в навигации, строке или соседнем блоке, не повторяется в заголовках и подзаголовках | глаза, железное правило 12 |
| Текст сокращён без потери смысла: лишних слов нет, один объект — один термин (правило 15) | глаза |
| У последней строки каждого списка нет разделителя (`Show Divider = false`), отдельный `Divider` не стоит первым или последним в контейнере | скрипт-проверка из железного правила 10, затем глаза |
| Контент оверлеев лежит в слоте, а не дорисован внутри панели | глаза |
| Проверено в обеих модах `Theme` и в нужной моде `Platform` | глаза, переключением мод на корне |
| Состояния: матрица заполнена, пропуски собраны по просьбе или записаны в ревью | `references/states-audit.md`: матрица, скрипт, снимки |
| Недостающее в SU10 — локальный компонент в своём файле, а не разовые фреймы; Nurla предупреждён | глаза, см. «Чего в системе нет» |

## Что не трогать

- **`MultiSelect`** — нетокеновые значения в нём внесены владельцем намеренно, не «чинить»
- **`Loading`** — мастер донастроен владельцем
- **Палитру и шкалы** не чистить по признаку «не используется»: примитивы, ступени `Space-*`, `radius/*`, `height/*`, семантические роли и текстовые стили держатся полными
- **Имена токенов с историей**: `icon/tertuary-black-static` (опечатка) и `surface/orange-*` (по значению yellow) переименованию не подлежат — сломаются привязки
- **Логотип в моках** (`Logo_JUZ40` в MobileHeader, текст `JUZ40` в примере Action Panel) — это название продукта на макете, а не имя системы; переименование дски его не касается
- **Осознанные отклонения** от правил, если они описаны в паспорте: разные размеры иконок в `Tab` и `Control > Label`, прозрачный фон `badge/neutral`, порядок «подпись, затем значение» в Action Panel

## Чего в системе нет — локальный компонент в своём файле

Сейчас в SU10 нет:

- **Empty state** как компонента нет — пустой список собирается по рецепту «Пустой результат» (иллюстрация + `Heading` S + `Button`), не из `Alert`
- **Chart / график** — ни линейного, ни столбчатого, ни осей
- **Carousel** (`ProgressBar` есть с 4.5.0, `Slider`, `RangeSlider` и `Skeleton` — с 16.11; загрузка файла — `FileDropzone` с 4.33.0)
- **Time picker** — календарь выбирает только дату
- **Comment / элемент ленты** — реакций, ответов и вложений нет. Сама карточка «автор + роль + дата + текст» теперь собирается из `ProfileItem` `Size=S`: роль — `Badge`, дата — `Meta`, текст — `Body`
- **Avatar group** (статус-точка на аватаре есть — `Show Status`)
- **Логотипов соцсетей, кроме YouTube, Telegram, Instagram, TikTok и WhatsApp** — первые четыре цветными лежат в паке (`Color / Social`, см. `SocialLink`), WhatsApp и плоский Telegram — в стиле Bold. VK и другие переносятся из исходного макета клоном

### Что делать, если элемента нет

| Ситуация | Что делать |
|---|---|
| У существующего компонента нет нужного состояния или свойства | правило 17, запись в `component-proposals.md` |
| Элемента нет в системе совсем | локальный компонент в своём файле: `new-component.md`, раздел «Локальный компонент» |
