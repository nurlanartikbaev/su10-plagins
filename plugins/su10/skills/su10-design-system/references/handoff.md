# Хэндофф в разработку — как собирать секции сценариев

Справочник скилла `su10-design-system`. Основной файл отвечает на вопрос «как собрать экран»,
этот — «как разложить экраны так, чтобы разработчик понял поток без созвона».

**Когда открывать:** просят собрать «все стейты и сценарии» экрана, «несколько вариантов»,
«светлую тему», «десктоп-версию», «подготовь к хэндофу / к разработке», «убери лишнее перед
передачей». Для сборки одного экрана без доски он не нужен.

---

## 1. Жизненный цикл: варианты → выбор → сценарии → хэндофф

| Этап | Что на доске | Как называется |
|---|---|---|
| Варианты | 3–4 разных решения одной задачи рядом, у каждого пара тем | дорожка `<Буква> · <Тема> (варианты на выбор)`, коды `Т1…Т4`, `ДК1…ДК3`, `Л1…Л4` |
| Выбор | владелец назвал код — под него дорожка состояний; варианты остаются | `<Буква> · <Название> (<код>): состояния и сценарии` |
| Итерация | правка выбранного варианта — **новая дорожка рядом**, старое не трогать, пока не попросят удалить | новые коды, в заметке — от чего отталкивались |
| Хэндофф | варианты и дубли удалены, дорожки перенумерованы, тексты без уточнений | секция `<Раздел> — сценарии для разработки` |

Варианты должны различаться **устройством**, а не цветом кнопки: где живёт навигация, что видно
сразу, что открывается кликом. В заметке под вариантом — в чём его идея и чем он платит.

## 2. Устройство секции

Одна секция — один раздел продукта (`Страница курса`, `Список уроков`, `Курсы`). Внутри —
дорожки (lanes) сверху вниз, в дорожке — экраны слева направо в порядке сценария.

**Подписи доски — только компонентами `Handoff*`** со страницы **Documentation Assets**,
паспорт `HandoffPassport` (`3028:216`) там же. Текст руками и чужой `Note` из внешней
библиотеки на доску не ставят: до 16.10 так и было, все доски переведены на компоненты.

| Элемент | Компонент | Свойства | Позиция |
|---|---|---|---|
| Шапка секции | `HandoffHeader` `3026:216` · key `26e067dc6a599a617194e78a618e60094dc2dac8` | `Title#3026:0`, `Description#3026:1`, `Show Description#3026:2` | x 100, y 40 |
| Заголовок дорожки | `HandoffLane` `3026:219` · key `a3eca3a1994c95b493f282b428f815fc6d8bdf70` | `Title#3026:3`, `Subtitle#3026:4`, `Show Subtitle#3026:5` | x 100, на 190 выше экранов |
| Подпись экрана | `HandoffScreenLabel` `3026:222` · key `3b9e0ad27105459d985d47493594cb528279c1ed` | `Title#3026:6`, `When#3026:7`, `Show When#3026:8` | над тёмным экраном пары, y − 66 |
| Заметка | `HandoffNote` (набор) `3026:229` · key `3915dd9e8b05e84c9cdfb0fd91317e410fce6048` | `Text#3026:9`; `Type` Заметка / Анимация | под тёмным экраном, низ + 32 |
| Стрелка | коннектор-образец `HandoffArrow · образец` `3028:306` в паспорте | — | см. §5 |

- `HandoffHeader` и `HandoffLane` — ширина 1400; `HandoffScreenLabel` — 480 (длинное название —
  шире, чтобы не переносилось и не наезжало на экран); `HandoffNote` — 260, высота по тексту.
- Несколько заметок под одним экраном — стопкой с шагом 12, следующая начинается под
  предыдущей: высота заметки зависит от текста, на глаз её не угадать.
- Тексты на стилях системы (Heading 1/2/3, Body 1, Body 3), цвета `text/primary` /
  `text/secondary`, заметка — `surface/blue-static` или `purple-static` с `text/white-static`.

**Сетка.**

| | Экран | Пара тем | Шаг колонок | Шаг рядов |
|---|---|---|---|---|
| Телефон | 375 × 852 (длинный скролл — HUG по контенту, экран целиком) | светлая на x + 415 | 1100 | высота самого длинного + ~600 |
| Десктоп | 1440 × 1024 | светлая на x + 1520 | 3400 | 1700 |

Шаг колонок оставляет место под подпись стрелки между парами. Экраны начинаются с x 1100:
левые 1000 px — под заголовки дорожек. Дорожка начинается с экрана-входа («откуда пришёл»).

```js
// подписи доски — инстансами Handoff*; id и свойства — из таблицы выше
const [HDR, LANE, LBL, NOTE] = await Promise.all(
  ['3026:216', '3026:219', '3026:222', '3026:229'].map(id => figma.getNodeByIdAsync(id)));
for (const c of [HDR, LANE, LBL, ...NOTE.children])
  for (const t of c.findAll(n => n.type === 'TEXT')) await figma.loadFontAsync(t.fontName);
function put(comp, x, y, props) { const i = comp.createInstance(); sec.appendChild(i);
  i.x = x; i.y = y; i.setProperties(props); return i; }
put(LANE, 100, screenY - 190, { 'Title#3026:3': 'А · Прохождение курса', 'Show Subtitle#3026:5': false });
put(LBL, screenX, screenY - 66, { 'Title#3026:6': 'А2 · В процессе', 'When#3026:7': 'Когда: открыл курс' });
const note = NOTE.children.find(v => v.name === 'Type=Заметка');
put(note, screenX, screenY + screenH + 32, { 'Text#3026:9': 'Экран открывается прокрученным к текущей неделе.' });
```

## 3. Имена и тексты

- **Фрейм экрана:** `<Раздел> / <код> · <название> · <тема>` — `Аналитика / И5 · Результаты курса · тёмная`.
  Десктоп: `<Раздел> · десктоп / …`. По этому имени разработчик ищет экран в Dev Mode.
- **Код** = буква дорожки + номер в порядке сценария. При чистке перед хэндофом нумерация
  сквозная, без дыр после удалённых вариантов.
- **«Когда:»** — действие пользователя его словами: `Когда: нажал «Итог месяца»`, а не
  `Когда: state = monthResult`.
- **Заметка** — что изменилось на экране и почему, правило для разработки. Без уточнений вида
  «выбран», «моё предложение», «пример», «взято из концептов», «можно обсудить» — на хэндоффе
  это шум. Открытые вопросы — владельцу в чат, не на доску.
- **Данные сквозные:** одни и те же имена, баллы, недели на всех экранах потока; имена в
  рейтинге не повторяются, суммы сходятся. Плейсхолдеры («Название задачи», «Заголовок»)
  на продуктовых экранах — ошибка.

## 4. Темы: тёмная слева, светлая справа

- Каждый экран — **пара**: тёмная слева, светлая справа на одной высоте. Не отдельной дорожкой.
- Светлая = клон тёмной + мода `Theme` на корне. Пересобирать руками нельзя — разъедутся.
  ```js
  const light = dark.clone(); light.x = dark.x + 415;  // десктоп: + 1520
  light.setExplicitVariableModeForCollection(themeCollection, LIGHT_MODE_ID);
  light.name = dark.name.replace('· тёмная', '· светлая');
  ```
- **Всегда-тёмные части** (космический фон карты курса) несут явную моду Dark **на своём
  фрейме** — тогда переключение корня их не трогает.
- Шторка поверх всегда-тёмной карты **следует теме приложения**: пара = «карта + тёмная
  шторка» | «карта + светлая шторка».
- Обе темы смотрят скриншотом: токен, верный в одной теме, в другой даёт белое на белом.

## 5. Стрелки

Каждый переход между экранами — коннектор с подписью действия. Без стрелок доска читается
как галерея, а не как поток.

```js
const a = (await figma.getNodeByIdAsync('3028:306')).clone(); sec.appendChild(a);  // образец из HandoffPassport
a.connectorStart = { endpointNodeId: fromLight.id, magnet: 'RIGHT' };  // из СВЕТЛОГО экрана пары
a.connectorEnd   = { endpointNodeId: toDark.id,   magnet: 'LEFT'  };  // в ТЁМНЫЙ следующей
await figma.loadFontAsync(a.text.fontName); a.text.characters = 'нажал «Итог месяца»';
```

Тип `STRAIGHT`, толщина 4, стрелка только на конце. Переход во второй ряд (экран результатов
под списком) — вертикальная стрелка `BOTTOM` → `TOP` между светлыми экранами.

## 6. Откуда брать экраны

- **Только компоненты дски** (железные правила 1–3). Блок, уже собранный на соседнем экране
  сценария (Island со списком, Accordion месяца, Dock), **клонируют**, а не собирают заново —
  так данные и отступы совпадают по всему потоку.
- **Экраны из `redesign` и концептов** переносят **клоном** в секцию хэндоффа, оригиналы не
  трогают (железное правило 8). Опечатки, плейсхолдеры и самодельные элементы чинят в копии.
- Появился компонент, который раньше рисовали руками (например `ProgressBar`), — на хэндоффе
  самоделки заменяют им. После подмены — §9, «устаревшая ширина».

## 7. Десктоп из шаблона с верхней навигацией

Шаблон — десктоп-экраны владельца в `redesign`: тёмный `2254:15859`, светлый `2250:15099`
(1440 × 1024). Внутри: `Header` (верхняя навигация, абсолютно сверху) и `Content`
(1440 × 972, поля 20 / 24). Мода `Platform = Desktop` уже стоит на корне.

```js
async function screen(theme, name, x, y) {
  const tpl = await figma.getNodeByIdAsync(theme === 'dark' ? '2254:15859' : '2250:15099');
  const f = tpl.clone(); sec.appendChild(f); f.x = x; f.y = y; f.name = name;
  const c = f.children.find(k => k.name === 'Content');
  for (const k of [...c.children]) k.remove();
  c.layoutMode = 'VERTICAL'; c.itemSpacing = 20;
  c.primaryAxisSizingMode = 'FIXED'; c.counterAxisSizingMode = 'FIXED'; c.resize(1440, 972);
  return { f, c };  // дальше: шапка страницы + body (HORIZONTAL, FILL)
}
```

- **Шапка страницы:** `Button` Only Icon «назад» + `Heading` `Size=L` (название + подзаголовок,
  FILL) + действия справа `Button` Secondary с иконкой. Меню «⋯» с телефона на десктопе
  раскрывают в кнопки — места хватает.
- **Колонки:** основная FILL, боковая 448 (две колонки) или 400 (три колонки), промежуток 24.
  Длинный список — в обёртке `clipsContent` на FILL по высоте: это прокрутка внутри колонки.
- **Мобильные блоки** (Island, Accordion, Dock, SegmentedControlRow) клонируют прямо в
  десктоп: размеры переключает мода `Platform` корня.
- **Мобильная карта курса шириной 375** в широкой панели теряется: линии месяцев обрываются,
  по бокам пусто. Растягивать нельзя — либо панель 560 и `rescale(1.3)`, либо навигация по
  неделям отдельной прямой линией.

## 8. Чистка перед хэндоффом — чек-лист

| Пункт | Как |
|---|---|
| Варианты, черновые дорожки и дубли удалены | дубль = экран выбранного варианта, повторённый в дорожке состояний |
| Дорожки и коды перенумерованы без дыр | §3 |
| В заголовках и заметках нет уточнений | §3 |
| Нет плейсхолдеров, опечаток, повторённых имён, несходящихся сумм | глаза по каждому экрану |
| У каждого экрана есть пара светлой темы | §4 |
| Каждый переход — стрелка с подписью | §5 |
| Под каждым экраном «Когда:» и заметка | §2 |
| Все подписи доски — инстансы `Handoff*`, ни текста руками, ни чужого `Note` | §2 |
| Самодельные элементы заменены компонентами, где они появились | §6 |
| Нет разделителя под последней строкой списков | железное правило 10 |
| Экраны прошли `audit.md`, изменённые кадры сняты скриншотом | `audit.md` |
| Секция переименована в `<Раздел> — сценарии для разработки` | |
| **Статус Ready for development** | Plugin API не поддерживает `devStatus` (чтение и запись падают ошибкой) — **владелец ставит руками**, об этом говорят в отчёте |

## 9. Ловушки, проверено на доске

- **Глубокий `findAll` по большой секции падает по таймауту.** Обходить стеком и не заходить
  внутрь инстансов, если искомое лежит снаружи:
  ```js
  const st = [...sec.children]; while (st.length) { const x = st.pop();
    if (x.type === 'INSTANCE') { /* проверить сам инстанс */ continue; }
    if ('children' in x) st.push(...x.children); }
  ```
- **Устаревшая ширина после подмены в слоте инстанса.** Заменил слой внутри слота (линию на
  `ProgressBar`) — Figma держит старые ширины: строка FILL остаётся 326 вместо 888, колонка
  схлопывается до 1 px, соседи наезжают. Лечится переключением сайзинга у всех предков:
  ```js
  let p = node.parent; const chain = [];
  while (p && p.type !== 'SECTION') { chain.unshift(p); p = p.parent; }
  for (const a of chain) if (a.layoutSizingHorizontal === 'FILL' && a.parent.layoutMode !== 'NONE') {
    a.layoutSizingHorizontal = 'FIXED'; a.layoutSizingHorizontal = 'FILL'; }
  ```
  После любой массовой подмены — скриншот каждого затронутого экрана, а не одного.
- **`Button` Only Icon `Signal=Success, Weight=Tertiary, State=Pressed`** (кнопка мобильной
  шапки) красит Outline-иконку в зелёный. В шапке телефона цвет иконки переопределён — в новых
  экранах так же: заливку вектора иконки копируют с иконки мобильной шапки.
- **ID локального текстового стиля кончается запятой** (`S:18ec…f0,`). Без запятой
  `getStyleByIdAsync` возвращает `null`.
- **Состояние и тексты `Course map / Dock`** ставят двумя вызовами `setProperties`: сначала
  вариант, потом тексты. Так собраны все экраны доски, и тексты не слетают.
- **Иконки, которых нет в файле**, импортируют по ключу из SU10 Icon Pack
  (`importComponentByKeyAsync`), ключ ищется `search_design_system`. Только Outline.
- Остальное про клоны, слоты и `resize()` — в основном файле, раздел «Сборка через Figma Plugin API».

## 10. Отчёт владельцу

Коротко: что собрано и где (имя секции), какие дорожки, что проверено скриншотами, **какие
данные придуманы** (баллы, даты), что сделать руками (Ready for development) и где нужен
компонент, которого нет в системе.
