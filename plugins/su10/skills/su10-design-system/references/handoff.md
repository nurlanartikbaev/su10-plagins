# Хэндофф в разработку — как собирать секции сценариев

Справочник скилла `su10-design-system`. Основной файл отвечает на вопрос «как собрать экран»,
этот — «как разложить экраны так, чтобы разработчик понял поток без созвона».

**Когда открывать:** просят собрать «все стейты и сценарии» экрана, «несколько вариантов»,
«светлую тему», «десктоп-версию», «подготовь к хэндофу / к разработке», «убери лишнее перед
передачей». Для сборки одного экрана без доски он не нужен.

---

## 1. Жизненный цикл: варианты → выбор → сценарии → хэндофф

| Этап | Что на доске | Как называется |
|---|---|---|
| Варианты | 3–4 разных решения одной задачи рядом, у каждого пара тем | дорожка `<Буква> · <Тема> (варианты на выбор)`, коды `Т1…Т4`, `ДК1…ДК3`, `Л1…Л4` |
| Выбор | владелец назвал код — под него дорожка состояний; варианты остаются | `<Буква> · <Название> (<код>): состояния и сценарии` |
| Итерация | правка выбранного варианта — **новая дорожка рядом**, старое не трогать, пока не попросят удалить | новые коды, в заметке — от чего отталкивались |
| Хэндофф | варианты и дубли удалены, дорожки перенумерованы, тексты без уточнений | секция `<Раздел> — сценарии для разработки` |

Варианты должны различаться **устройством**, а не цветом кнопки: где живёт навигация, что видно
сразу, что открывается кликом. В заметке под вариантом — в чём его идея и чем он платит.

## 2. Устройство секции

Одна секция — один раздел продукта (`Страница курса`, `Список уроков`, `Курсы`). Внутри —
дорожки (lanes) сверху вниз, в дорожке — экраны слева направо в порядке сценария.

**Порядок — всегда по пути пользователя** (решение владельца 29.10). Доска читается как
сценарий, а не как история работы, поэтому после каждого добавления или удаления экранов её
перекладывают заново:
- **Дорожки сверху вниз** — в том порядке, в котором человек их проходит: первый запуск или
  вход (первая цель, онбординг) → основной сценарий → действия над результатом (смена цели,
  редактирование) → особые состояния страницы → состояния входной точки (баннер, карточка).
- **Внутри дорожки** — шаги слева направо; ветки и исключения («не закончен», «время вышло»)
  стоят после основного потока той же дорожки, а не в отдельной дорожке и не в середине.
- **Буквы и номера перенумеровывают под этот порядок** — без дыр. Вместе с именами фреймов
  правят подписи «Когда:», ссылки на коды в заметках («ведёт в А3») и описание секции
  (`DocHeading`). Замену кодов делают одним проходом через словарь «старый → новый», иначе
  А→Б и Б→В затирают друг друга.
- **Подписи и заметки едут вместе со своим тёмным экраном**: перед перекладкой собрать их по
  позиции (подпись — над экраном, заметки — под ним), сдвигать на ту же дельту. Заголовки
  дорожек проще пересоздать. В конце — проверка «заметок без экрана»: после удалённых экранов
  они остаются висеть.

**Подписи доски собирают из компонентов, которые уже есть в системе** — отдельных
компонентов под доску не заводят (решение владельца 16.10: `Handoff*` были созданы и удалены).
Текст руками и чужой `Note` из внешней библиотеки на доску тоже не ставят.

| Элемент | Компонент | Как заполнить | Позиция |
|---|---|---|---|
| Шапка секции | `DocHeading` `1745:95` | `Title#1745:0`; описание — текстовый слой `Description` (нет описания — скрыть его фрейм) | x 100, y 40, ширина 1400 |
| Паспорт задачи | `TaskPassport` `3238:97430` | название, описание, автор и от кого, ссылки (`Show Confluence`, `Show Jira`, `Show Link 1–3`), до четырёх метрик (`Metric N`, `Metric N Goal`, `Show Metric N`) | под шапкой секции, x 100, до первой дорожки экранов |
| Заголовок дорожки | `Heading` `Size=L` (набор `1386:23`) | `Title#1386:0` — «<Буква> · <Название>»; `Subtitle#1386:4` + `Show Subtitle#1386:8` | x 100, на 190 выше экранов, ширина 1400 |
| Подпись экрана | `Heading` `Size=M` | `Title#1386:0` — «<код> · <название>»; `Subtitle#1386:4` — «Когда: …» | низ на 18 px над тёмным экраном пары, ширина 480 (длинное название — шире) |
| Заметка | `Alert` (набор `550:15590`) `Weight=Primary, Signal=Info`; заметка про анимацию — `Weight=Secondary, Signal=Info` | `Closable#3361:0`, `Show Title#3361:2`, `Show Buttons #3363:8` — `false`; текст — слой `Subtitle` | под тёмным экраном, низ + 32, ширина 320 |
| Стрелка | клон коннектора из того же файла | см. §5 | — |

- **У `Alert` описание обрезается на третьей строке** — в заметке снимают ограничение:
  `subtitle.textTruncation = 'DISABLED'; subtitle.maxLines = null`. Без этого длинная
  заметка молча кончается многоточием.
- Несколько заметок под одним экраном — стопкой с шагом 12, следующая начинается под
  предыдущей: высота зависит от текста, на глаз её не угадать. Две заметки рядом — шаг по x
  = ширина + 24, иначе 320-пиксельные наедут друг на друга.

**Сетка.**

| | Экран | Пара тем | Шаг колонок | Шаг рядов |
|---|---|---|---|---|
| Телефон | 375 × 852 (длинный скролл — HUG по контенту, экран целиком) | светлая на x + 415 | 1100 | высота самого длинного + ~600 |
| Десктоп | 1440 × 1024 | светлая на x + 1520 | 3400 | 1700 |

Шаг колонок оставляет место под подпись стрелки между парами. Экраны начинаются с x 1100:
левые 1000 px — под заголовки дорожек. Дорожка начинается с экрана-входа («откуда пришёл»).

```js
// подписи доски — компонентами системы
const DOC = await figma.getNodeByIdAsync('1745:95');                 // DocHeading
const HEAD = await figma.getNodeByIdAsync('1386:23');                // Heading
const ALERT = await figma.getNodeByIdAsync('550:15590');             // Alert
const hL = HEAD.children.find(v => v.name === 'Size=L'), hM = HEAD.children.find(v => v.name === 'Size=M');
const note = ALERT.children.find(v => v.name === 'Weight=Primary, Signal=Info');
for (const c of [DOC, hL, hM, note]) for (const t of c.findAll(n => n.type === 'TEXT')) await figma.loadFontAsync(t.fontName);
function put(comp, x, y, w, props) { const i = comp.createInstance(); sec.appendChild(i);
  if (props) i.setProperties(props); i.resize(w, i.height); i.x = x; i.y = y; return i; }
put(hL, 100, screenY - 190, 1400, { 'Title#1386:0': 'А · Прохождение курса', 'Show Subtitle#1386:8': false });
const lbl = put(hM, screenX, 0, 480, { 'Title#1386:0': 'А2 · В процессе', 'Subtitle#1386:4': 'Когда: открыл курс' });
lbl.y = screenY - 18 - lbl.height;
const n = put(note, screenX, screenY + screenH + 32, 320,
  { 'Closable#3361:0': false, 'Show Title#3361:2': false, 'Show Buttons #3363:8': false });
const sub = n.findOne(t => t.type === 'TEXT' && t.name === 'Subtitle');
sub.characters = 'Экран открывается прокрученным к текущей неделе.'; sub.textTruncation = 'DISABLED'; sub.maxLines = null;
```

## 3. Имена и тексты

- **Фрейм экрана:** `<Раздел> / <код> · <название> · <тема>` — `Аналитика / И5 · Результаты курса · тёмная`.
  Десктоп: `<Раздел> · десктоп / …`. По этому имени разработчик ищет экран в Dev Mode.
- **Код** = буква дорожки + номер в порядке сценария. При чистке перед хэндофом нумерация
  сквозная, без дыр после удалённых вариантов.
- **«Когда:»** — действие пользователя его словами: `Когда: нажал «Итог месяца»`, а не
  `Когда: state = monthResult`.
- **Заметка** — что изменилось на экране и почему, правило для разработки. Без уточнений вида
  «выбран», «моё предложение», «пример», «взято из концептов», «можно обсудить» — на хэндоффе
  это шум. Открытые вопросы — владельцу в чат, не на доску.
- **Данные сквозные:** одни и те же имена, баллы, недели на всех экранах потока; имена в
  рейтинге не повторяются, суммы сходятся. Плейсхолдеры («Название задачи», «Заголовок»)
  на продуктовых экранах — ошибка.

## 4. Темы: тёмная слева, светлая справа

- Каждый экран — **пара**: тёмная слева, светлая справа на одной высоте. Не отдельной дорожкой.
- Светлая = клон тёмной + мода `Theme` на корне. Пересобирать руками нельзя — разъедутся.
  ```js
  const light = dark.clone(); light.x = dark.x + 415;  // десктоп: + 1520
  light.setExplicitVariableModeForCollection(themeCollection, LIGHT_MODE_ID);
  light.name = dark.name.replace('· тёмная', '· светлая');
  ```
- **Всегда-тёмные части** (космический фон карты курса) несут явную моду Dark **на своём
  фрейме** — тогда переключение корня их не трогает.
- Шторка поверх всегда-тёмной карты **следует теме приложения**: пара = «карта + тёмная
  шторка» | «карта + светлая шторка».
  Светлая пара такого экрана — **не** мода Light на корне: корень остаётся `Dark`, мода `Light` ставится только на шторку (`MobileBottomSheet`). Иначе липкая шапка с плашкой места светлеет поверх тёмной карты (так было 20.10 на Ж2).
- Обе темы смотрят скриншотом: токен, верный в одной теме, в другой даёт белое на белом.

## 4а. Языки: две секции, русская и казахская

Решение владельца 05.11. На хэндофф всегда идут две соседние секции: одна на русском, вторая на казахском. Это правило для каждой подготовки к хэндоффу, отдельно о нём не просят.

- **Положение:** казахская секция стоит сразу за русской, справа, верх на одной высоте, промежуток 200.
- **Сборка:** сначала готовят русскую секцию целиком. Казахская — её клон, поэтому сетка, коды экранов, темы и стрелки совпадают.
- **Имя секции:** `<Раздел> — сценарии для разработки · қазақша`. Имя фрейма: `<Раздел> / <код> · <название> · <тема> · қазақша`.
- **Что переводят:** все тексты на экранах. Подписи доски (`DocHeading`, «Когда:», заметки, подписи стрелок) остаются на русском: их читает разработчик.
- **Текст:** обращение на «сіз». Один объект — один термин на всех экранах. Смешанных строк нет: «Черновик сақталған» — ошибка.
- **Длина:** казахский длиннее русского на 20–30 %. Проверь снимком каждый экран обеих тем: перенос, обрезка, кнопки.
- **Перевод:** сначала бери тексты из продукта. Перевод, которого в продукте нет, покажи владельцу отдельным списком.
- **Стрелки:** после клонирования проверь, что концы каждой стрелки ведут на экраны своей секции.
- **Экраны пришли на одном языке:** вторую секцию собирают из них по тем же правилам.
- **Плавающие элементы:** подсказка рядом с кнопкой стоит по левому краю и на длинном тексте заходит на кнопку. На казахском её сдвигают так, чтобы зазор совпал с русским экраном.
- **Правка после сборки:** изменение макета вносят в обе секции. Иначе они разойдутся.

## 5. Стрелки

Каждый переход между экранами — коннектор с подписью действия. Без стрелок доска читается
как галерея, а не как поток.

```js
// образец ищут в файле: id из другого файла и старые id здесь не работают
let src = null;
for (const p of figma.root.children) { await p.loadAsync();
  src = p.findAllWithCriteria({ types: ['CONNECTOR'] })[0]; if (src) break; }
const a = src.clone(); sec.appendChild(a);
a.connectorStart = { endpointNodeId: fromLight.id, magnet: 'RIGHT' };  // из СВЕТЛОГО экрана пары
a.connectorEnd   = { endpointNodeId: toDark.id,   magnet: 'LEFT'  };  // в ТЁМНЫЙ следующей
await figma.loadFontAsync(a.text.fontName); a.text.characters = 'нажал «Итог месяца»';
```

**Новую стрелку скриптом не создать:** `figma.createConnector` в дизайн-файле недоступен,
работает только клон существующей. В файле нет ни одной стрелки — доску сначала переносят в
чистовой файл, где они есть, и ставят стрелки там, после вставки (`team-workflow.md`, §5.4).
Ни там, ни там нет — одну стрелку рисует человек, остальные клонируются с неё.

Тип `STRAIGHT`, толщина 4, стрелка только на конце. Переход во второй ряд (экран результатов
под списком) — вертикальная стрелка `BOTTOM` → `TOP` между светлыми экранами.

**Цвет стрелки: её должно быть видно** (решение владельца 04.11). У клона стоит `border/secondary`, он сливается с серым фоном секции. После клонирования ставь `border/info`, ключ `63224a23d3ba04d909d53c8684b29cfa58ac8065`: синий виден на сером, тёмном и светлом экране. Цвет проверяй снимком секции.

```js
const info = await figma.variables.importVariableByKeyAsync('63224a23d3ba04d909d53c8684b29cfa58ac8065');
a.strokes = JSON.parse(JSON.stringify(a.strokes)).map(p => figma.variables.setBoundVariableForPaint(p, 'color', info));
```

**Стрелка не идёт через экраны** (решение владельца 04.11). Сначала раскладка, потом стрелки:

- Шаг колонок соблюдают: десктоп 3400, телефон 1100. В промежутке помещается подпись стрелки.
- Экраны одной дорожки стоят в один ряд, без переноса с конца ряда в начало следующего.
- Следующая дорожка начинается под последним экраном предыдущей. Переход — вертикальная стрелка `BOTTOM` → `TOP` между светлыми экранами. Нижний ряд сдвинут вправо, а не начинается слева.
- Заголовок дорожки стоит над её первым экраном и не шире тёмного экрана: вертикальная стрелка идёт по светлой колонке.
- Экран с несколькими ветками: каждая ветка в своём ряду, первый экран ветки в следующей колонке. Стрелки расходятся `RIGHT` → `LEFT` по промежутку между колонками и не задевают экраны. Вертикаль `BOTTOM` → `TOP` занимает только экран прямо под родителем.
- Ветка, которая уходит вбок от основного пути, не стоит в конце основного ряда: её выносят в свой ряд под экраном, откуда она начинается. Доску ниже сдвигают, код экранов не меняют.
- Стрелка всегда `STRAIGHT`: у клона может остаться `ELBOWED`, и он гнёт линию.
- Проверка: у стрелки не должно быть диагонали через ряд. После перестановки перезапиши `connectorStart` и `connectorEnd`, затем посмотри снимок.
- Имя коннектора: `Стрелка · <подпись>`. Клон сохраняет имя образца, его нужно заменить.

## 6. Откуда брать экраны

- **Только компоненты дски** (железные правила 1–3). Блок, уже собранный на соседнем экране
  сценария (Island со списком, Accordion месяца, Dock), **клонируют**, а не собирают заново —
  так данные и отступы совпадают по всему потоку.
- **Экраны из `redesign` и концептов** переносят **клоном** в секцию хэндоффа, оригиналы не
  трогают (железное правило 8). Опечатки, плейсхолдеры и самодельные элементы чинят в копии.
- Появился компонент, который раньше рисовали руками (например `ProgressBar`), — на хэндоффе
  самоделки заменяют им. После подмены — §9, «устаревшая ширина».

## 7. Десктоп из шаблона с верхней навигацией

Шаблон — десктоп-экраны владельца в `redesign`: тёмный `3258:100612` (К6), светлый `3258:100350` (К7) — с 20.10 это актуальные экраны «Курсов», до этого были `2254:15859` / `2250:15099`
(1440 × 1024). Внутри: `Header` (верхняя навигация, абсолютно сверху) и `Content`
(1440 × 972, поля 20 / 24). Мода `Platform = Desktop` уже стоит на корне.

```js
async function screen(theme, name, x, y) {
  const tpl = await figma.getNodeByIdAsync(theme === 'dark' ? '3258:100612' : '3258:100350');
  const f = tpl.clone(); sec.appendChild(f); f.x = x; f.y = y; f.name = name;
  const c = f.children.find(k => k.name === 'Content');
  for (const k of [...c.children]) k.remove();
  c.layoutMode = 'VERTICAL'; c.itemSpacing = 20;
  c.primaryAxisSizingMode = 'FIXED'; c.counterAxisSizingMode = 'FIXED'; c.resize(1440, 972);
  c.primaryAxisAlignItems = 'MIN';  // у шаблона CENTER: без этого короткая страница уезжает в середину
  return { f, c };  // дальше: шапка страницы + body (HORIZONTAL, FILL)
}
```

- **Шапка страницы:** `Button` Only Icon «назад» + `Heading` `Size=L` (название + подзаголовок,
  FILL) + действия справа `Button` Secondary с иконкой. Меню «⋯» с телефона на десктопе
  раскрывают в кнопки — места хватает.
- **Колонки — по сетке шаблона** (12 × 94, поля 24, промежуток 24; таблица ширин — в SKILL.md,
  «Сетка десктопа»): боковая 3 или 4 колонки (330 / 448), основная — остаток на FILL.
  Длинный список — в обёртке `clipsContent` на FILL по высоте: это прокрутка внутри колонки.
- **Короткие экраны — одна колонка 920 на весь сценарий** (SKILL.md, «Сетка десктопа»): все
  экраны дорожек одного сценария стоят в одной ширине, включая шапку страницы.
- **Мобильные блоки** (Island, Accordion, Dock, SegmentedControlRow) клонируют прямо в
  десктоп: размеры переключает мода `Platform` корня.
- **Мобильная карта курса шириной 375** в широкой панели теряется: линии месяцев обрываются,
  по бокам пусто. Растягивать нельзя — либо панель 560 и `rescale(1.3)`, либо навигация по
  неделям отдельной прямой линией.

## 8. Чистка перед хэндоффом — чек-лист

| Пункт | Как |
|---|---|
| Варианты, черновые дорожки и дубли удалены | дубль = экран выбранного варианта, повторённый в дорожке состояний |
| Дорожки и экраны стоят по пути пользователя, коды перенумерованы без дыр | §2, §3 |

## 9. Ловушки, проверено на доске

- **Глубокий `findAll` по большой секции падает по таймауту.** Обходить стеком и не заходить
  внутрь инстансов, если искомое лежит снаружи:
  ```js
  const st = [...sec.children]; while (st.length) { const x = st.pop();
    if (x.type === 'INSTANCE') { /* проверить сам инстанс */ continue; }
    if ('children' in x) st.push(...x.children); }
  ```
- **Устаревшая ширина после подмены в слоте инстанса.** Заменил слой внутри слота (линию на
  `ProgressBar`) — Figma держит старые ширины: строка FILL остаётся 326 вместо 888, колонка
  схлопывается до 1 px, соседи наезжают. Лечится переключением сайзинга у всех предков:
  ```js
  let p = node.parent; const chain = [];
  while (p && p.type !== 'SECTION') { chain.unshift(p); p = p.parent; }
  for (const a of chain) if (a.layoutSizingHorizontal === 'FILL' && a.parent.layoutMode !== 'NONE') {
    a.layoutSizingHorizontal = 'FIXED'; a.layoutSizingHorizontal = 'FILL'; }
  ```
  После любой массовой подмены — скриншот каждого затронутого экрана, а не одного.
- **Кнопки-иконки.** В шапке телефона — `HeaderButton` `State=Rest`. На экране (фильтр рядом с поиском) — `Button` `Size=M, Signal=Info, Weight=Secondary, State=Rest, Only Icon=Yes`. `Button` `Signal=Success, State=Pressed` из старых шапок не копируют (железное правило 13 в `SKILL.md`).
- **ID локального текстового стиля кончается запятой** (`S:18ec…f0,`). Без запятой
  `getStyleByIdAsync` возвращает `null`.
- **Состояние и тексты `Course map / Dock`** ставят двумя вызовами `setProperties`: сначала
  вариант, потом тексты. Так собраны все экраны доски, и тексты не слетают.
- **Удаление экрана удаляет и стрелки, привязанные к нему.** Сначала перевяжи коннектор на новый экран (`connectorStart` / `connectorEnd`), потом удаляй старый. Скрипт, обратившийся к уже удалённой стрелке, падает и откатывается целиком.
- **Выбранный вариант встаёт на место старого экрана.** Новый экран получает x, y и имя старого (код не меняется), стрелки перевязываются, заметка правится. Потом старый экран удаляется, а дорожка вариантов — целиком.
- **Иконки, которых нет в файле**, импортируют по ключу из SU10 Icon Pack
  (`importComponentByKeyAsync`), ключ ищется `search_design_system`. Только Outline.
- Остальное про клоны, слоты и `resize()` — в основном файле, раздел «Сборка через Figma Plugin API».

- **Слот `DesktopDrawer` и `Heading` не держат ручной размер.** `content`: режим `FIXED` схлопывает слот до 92 × 18, и содержимое исчезает. Слот оставляют `HUG`, размер задают вложенному фрейму: ширина 388 и высота 938: поля 16 со всех сторон, под полем ввода нет пустоты. С подвалом высота меньше на его высоту. `action`: в инстансе направление менять нельзя. С 05.11 в мастере `Heading` слот горизонтальный, шаг `Space-16`, а шапка `DesktopDrawer` выровнена по центру с тем же шагом. Клон теряет имена кнопок в слоте, поэтому их ищут по индексу.
