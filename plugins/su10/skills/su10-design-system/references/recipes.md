# Рецепты сборки

Справочник скилла `su10-design-system`. **Когда открывать:** собираешь форму, таблицу, оверлей, экран, поиск, фильтр, состояния экрана, блок результата.

## Рецепты сборки

**Форма.** Вертикальный автолейаут, шаг между полями `Space-16`, между группами `Space-32`. Все поля одного размера. Ошибки — `State=Error` у поля плюс текст в `Show Description`, не отдельным Alert.

**Заголовок секции + шеврон = `Accordion`, не самодельная сборка.** Если в макете заголовок
блока умеет сворачивать/разворачивать содержимое под собой (типичный пример — «История по
месяцам ⌄» над таблицей), это готовый `Accordion` (`Size=M`, `State=Expanded`, `Show
Icon/Subtitle/Counter=false`, `Title` = текст заголовка, содержимое — в слот `content`), а
**не** `Subheading` с `Show Action=true` и самодельным `Text Button`-шевроном в слоте
действия. Разница не только в компонентах: у `Subheading`-варианта шеврон-кнопка (Text
Button, M ≈ 18–20px) выглядит прижатой/маленькой рядом с крупным заголовком, потому что
`Subheading` не предназначен нести роль сворачивания — это чисто визуальный ярлык, а
семантика «свернуть/развернуть» целиком принадлежит `Accordion`. Проверка перед сборкой:
если рядом с заголовком есть шеврон, который явно управляет видимостью блока ниже — сначала
ищи `Accordion`, а не собирай `Subheading + Text Button` по аналогии с шапкой оверлея.

**Таблица на телефоне — по задаче** (решение владельца 04.11). Значения сравнивают по столбцам — таблица с прокруткой вбок, без `Scrollbar`. Запись читают целиком — карточки: строка становится `Island` с `ListItem`, главное значение в заголовке, остальное в описании, статус — `Badge`. Примеры — раздел «Телефон» в паспорте Table.

**Таблица.** Вся таблица кладётся в `Island` с нулевыми полями. `TableHeaderCell` в строку заголовка, `TableFooter` снизу. Фильтры над таблицей — селекты и `SegmentedControlRow` размера S в одну строку.
Сборка бывает двух видов: **строками** — `TableRow` со слотом, если у строки есть состояния (выбор чекбоксом, наведение); **колонками** — вертикальные стопки `TableCell`, если состояний нет и важнее один раз задать ширину колонки. Смешивать в одной таблице нельзя. Подробности — в разделе «Таблицы данных» ниже.

**Оверлей.** `Overlay` на весь экран, поверх него `DesktopDrawer` у края, `MobileBottomSheet` внизу или `Dialog` по центру. Содержимое собирается отдельно и кладётся в слот `content` — внутрь самой панели ничего не дорисовывать.

**Шторку прибивают к низу экрана автолейаутом, а не координатой** (решение владельца 09.11). Шторку, поставленную `y = высота экрана − высота шторки`, сдвигает любая правка содержимого: скрыли подпись, пришло обновление библиотеки, сменили текст — шторка меняет высоту от верхнего края, и под ней появляется зазор (так было 09.11 на экранах отзыва, 18 px). Окно `Dialog` так же съезжает с центра. Порядок:
- корневой фрейм экрана — вертикальный автолейаут: `layoutMode = 'VERTICAL'`, размер `FIXED` (375 × 852 или 1440 × 1024), поля и шаг 0, `clipsContent = true`;
- фон экрана и `Overlay` — `layoutPositioning = 'ABSOLUTE'`, `x = 0`, `y = 0`;
- шторка — единственный ребёнок в потоке: `primaryAxisAlignItems = 'MAX'`, шторке `layoutSizingHorizontal = 'FILL'`;
- окно `Dialog` — тот же приём, но `primaryAxisAlignItems = 'CENTER'` и `counterAxisAlignItems = 'CENTER'`.
Проверка перед сдачей: у каждой шторки `высота экрана − (y + height) = 0`, у окна отступы сверху и снизу равны.

**Мобильный экран.** `Status Bar` + `MobileHeader v2` сверху (статус-бар залит стилем `BackgroundTop`, см. каталог), контент в `Island`-блоках, низ — `MobileBottomBar v2` (панель действий и таб-бар, лишнее выключается) и `Home Indicator` последним блоком. Мода `Platform = Mobile`.

**Десктоп.** Сверху `DesktopHeader v2` (ширина 1392, x 24, над контентом), сайдбар из `MenuItem`, контент в `Island`, действия — `Action Panel` с `Elevate=On`, если список длиннее экрана. Мода `Platform = Desktop`.

**Десктопный экран со списком или таблицей.** Самая частая раскладка, собирается так:

```
корневой фрейм          surface/1-layer  (в Light — серый #F7F7F7)
├─ шапка                surface/2-layer + нижняя обводка border/primary
├─ Breadcrumbs          на фоне страницы, без подложки
└─ строка контента      HORIZONTAL, gap 24, паддинги 32
   ├─ сайдбар           БЕЛАЯ КАРТОЧКА, ширина фиксированная
   └─ главная колонка   VERTICAL, gap 16
      ├─ блок фильтров  БЕЛАЯ КАРТОЧКА
      ├─ блок-заголовок БЕЛАЯ КАРТОЧКА
      └─ блок таблицы   БЕЛАЯ КАРТОЧКА (табы + таблица внутри одной)
```

Белая карточка = `surface/2-layer` + `radius/border-radius-400` (16) + обводка `border/primary` + паддинг 16. **Смысловой блок без подложки, прямо на сером фоне — ошибка**, и именно её проще всего не заметить: в Dark-теме порядок слоёв обратный, поэтому макет, собранный «по памяти» с мобильного тёмного экрана, в Light разваливается. Сверяйся с таблицей слоёв выше.

**Структура страницы.** `Heading` L сверху, дальше блоки `Island` со своими полями, в каждом `Heading` M или `Subheading`. `Divider` — только там, где отступа не хватает.

**Состояния экрана.** Загрузка блока с данными (баннер, карточка, виджет на странице) — **всегда скелетон** (решение владельца 12.11): плашки стоят на месте заголовка, чисел и графики, высота блока как у загруженного, блок не нажимается. Спиннер `Loading` в такой блок не ставят. Плашки — компонент `Skeleton` (с 16.11): строки `Heading`/`Body`/`Caption`, блоки `Block S/M/L`, `Circle`; раскладку берут из паспорта. Фреймами плашки больше не рисуют. Загрузка целой страницы, кнопки и выпадающего списка — по-прежнему `Loading`. Пусто у выпадающего списка — `Dropdown State=Empty`; пустой список на странице — рецепт «Пустой результат» ниже.

**Ошибка загрузки страницы или блока.** Страница не загрузилась: по центру области контента `Mascot` `Emotion=Oops` (160 на телефоне, 240 на десктопе), `Heading` `Size=S` с причиной («Не удалось загрузить курсы») и `Button` Secondary «Повторить» с иконкой `Refresh`. Не загрузился один блок: блок сохраняет свою высоту, внутри те же заголовок и кнопка, остальная страница работает. Ошибка действия пользователя — `Toast` Error, ошибка поля — `State=Error` у поля. Рецепт обобщает экраны «Курсы» К13 и К20.

**Недоступное содержимое не показывают** (решение владельца 16.11, отменяет решение 11.11 «блок приглушён и под замком»). Блок, который пользователю пока недоступен (форма, материалы, оценка, бланк ответов, содержимое закрытого урока), в макет не ставят: ни приглушённым, ни под замком. На его месте стоит `Alert` `Signal=Info`, `Weight=Secondary` без заголовка: что сделать, чтобы блок открылся.
- **Текст алерта** по правилу 15 и скиллу `ux-write`: действие в повелительном наклонении, условие через «если» или «чтобы», без длинного тире, на «вы». Примеры: «Сначала пройдите урок «Производная. Теория». Этот урок откроется сам.» · «Урок откроется 14 ноября в 19:00.» · «Досмотрите видео до 85%. После этого откроются оценка урока и материалы.» · «Сдайте устный тест куратору. Бланк ответов появится здесь после сдачи.»
- **Кнопку, которая ничего не может сделать, не ставят.** Урок закрыт по времени: кнопки действия нет. Нужно пройти другой урок: кнопка ведёт к нему.
- **Навигация остаётся.** Строка закрытого урока в списке недели — `ListItem` `State=Disabled`. Следующий шаг ленты, содержимое которого скрыто (интерактивное видео), — `ListItem` `State=Disabled` с Bold-замком в `Leading`: заголовок «Следом: <тип шага>», описание с условием.
- **Локального `LockTile` и своего фрейма с прозрачностью нет**: если они встретились в старом экране, блок удаляют и ставят `Alert`.
- **Порог просмотра видео в JUZ40 не унифицируют** (то же решение): он остаётся как на проде. У лекции и интерактивного видео в макетах 85%. В задании просмотр видео не считают, форму решения не закрывают.

**Поиск по списку.** `Text field` `Size=M`:
- `Show Label` и `Show Description` выключены, префикс — `Type=Icon` с иконкой `Magnifer`;
- плейсхолдер — «Поиск по <чему>»: «Поиск по задачам». Контекст («этой недели», «курса») не дописывают — он и так виден на экране;
- **после ввода — всегда крестик справа**: `Has Value=On`, `Show Suffix=true`, суффикс `Type=Icon` с `Outline / Essentional, UI / Close`. Нажатие стирает весь запрос. Крестик есть в любом состоянии с введённым текстом, не только в `Focused`; поле, пока вводят, — `State=Focused`.
- Правило только для поля-**поиска**. У обычного поля формы (имя, телефон, дата) крестика очистки нет — там суффикс по смыслу поля или выключен.

Поле и кнопка фильтра стоят **одной строкой над списком**: поле на `FILL`, кнопка — `Button` `Size=M, Signal=Info, Weight=Secondary, State=Rest, Only Icon=Yes`: светлая teal-плашка, как у соседних Secondary-кнопок (железное правило 13). Кнопку фильтра из шапки экрана при этом убирают: точка входа одна.

**Фильтр списка.**
- **Где открывается.** На телефоне — `MobileBottomSheet` «Фильтры». На десктопе — `Popover` на 8 px ниже кнопки фильтра: ширина по сетке (4 колонки = 448), правый край по краю колонки.
- **Popover фильтра изнутри** (вариант владельца): у `Content` поля `Space-0`, шаг `Space-8`; слот на `FILL` (по умолчанию HUG), шаг `Space-8`. Строка и группы лежат прямо в слоте, без обёртки.
- **Группы.** Подпись, `Text Button` «Сбросить» и `Tag`.
- **Кнопки.** «Сбросить» и «Применить» неактивны (`State=Disabled`), пока ничего не изменено.
- **Применённые фильтры** — строка `Tag` `Closable=Yes` над списком: крестик снимает фильтр без шторки.
- **Красная точка на кнопке фильтра** — `Show Dot=true`, пока применён хотя бы один фильтр. Пока фильтр только выбирают в шторке или поповере и ещё не применили — точки нет. Сняли все фильтры — точка гаснет. Точку не рисуют поверх кнопки руками: она живёт внутри компонента.
- **Список уроков: сегменты над поиском** (решение владельца 04.11). `SegmentedControlRow` «Все уроки» и «Рейтинговые» стоит первым, под ним поиск и фильтр. Это не фильтр: в шторке его нет, тега и красной точки он не даёт. Выбор недели — в фильтре, недель можно выбрать несколько.
- **Подзаголовок курса при нескольких неделях.** Одна неделя — «2 месяц 1 неделя». Недели подряд в одном месяце — «2 месяц 1–2 неделя». Недели не подряд или из разных месяцев — количество: «3 недели». На каждую неделю свой тег над списком и свой блок с заголовком недели.
- **Активные фильтры на телефоне — одной строкой со скроллом вбок**, до правого края экрана (`overflowDirection = HORIZONTAL`, `clipsContent`). В несколько строк теги не переносят. Теги применённых фильтров — `Tag` `State=Selected`, `Closable=Yes`.
- **Не повторять навигацию.** В фильтр не кладут то, что уже выбирается на странице: на десктопе неделя выбирается в линии, группы «Неделя» в поповере нет.
- **Бинарный признак списка** («только обязательные») — первая строка фильтра: `ListItem` с `Trailing` `Type=Toggle`. Не `SegmentedControlRow` «Все / X» над списком: сегмент «Все» повторяет «Все …» в группах фильтра и занимает строку.
- **Выравнивание.** У строки `ListItem` поля `Content` слева и справа `Space-12`, у групп те же `Space-12` — подписи групп встают по тексту строки. В шторке, где `ListItem` со своими 8, группы тоже 8.

**Маскот в состояниях.** Ошибка — `Oops`, успех — `Mascot` `Emotion=Celebrate` с анимацией «две хлопушки», остальное и правила генерации — в `references/mascot.md`.

**Пустой результат (поиск, фильтр).** Не `Alert`: он для событий и предупреждений, а не для пустого места. По центру области списка — сборка из трёх частей:
- иллюстрация — компонент `Mascot` `Type=Brand`, `Emotion=Search`, 160. `Search` только для пустого поиска; любое другое пустое состояние — всегда `Sad`, таблица в `references/mascot.md`, §2. Картинку с других экранов не клонируют;
- `Heading` `Size=S` с заголовком «Ничего не найдено» и подсказкой в подзаголовке. Запрос в подсказке не повторяют — он виден в поле;
- `Button` Secondary «Очистить поиск».


**Перенос ассетов из исходного макета.** Когда пересобираешь чужой экран на дске, картинки, логотипы и брендовые иконки не перерисовываются — они забираются из оригинала, иначе макет теряет узнаваемость и время уходит на заглушки:

```js
// фото/картинка → в свою фигуру или в слот picture у Avatar
const src = await figma.getNodeByIdAsync("25:20066");
thumb.fills = src.fills;                    // image paint переносится как есть

// логотип, брендовая иконка, готовая иллюстрация → клоном
const logo = (await figma.getNodeByIdAsync("I25:20307;20836:1977")).clone();
parent.appendChild(logo);
logo.resize(logo.width * (28 / logo.height), 28);   // пропорции сохраняются вручную
```

`clone()` работает и на потомке инстанса — копия отвязана и живёт самостоятельно. Градиенты карточек снимаются оттуда же: у исходного фрейма читается `fills[0].gradientStops` и подставляется в свой. Всё, что склонировано, а не собрано из дски, **подписывается в имени слоя** (`Chart (клон из оригинала — компонента графика нет в SU10)`), чтобы на ревью было видно границу системы.


**Рецепты без своего компонента** (решения владельца 16.11):
- **Запись голоса** собирают из готовых: `Button` Secondary «Начать запись» → во время записи `Button` `Signal=Error` «Остановить · 02:14» и `ProgressBar` → готовая запись строкой `FileItem` с `Show Remove` и `Button` Tertiary «Записать заново». Своего `AudioRecorder` нет. Иконки: `Video, Audio, Sound / Microphone`, `Call / Record Square`.
- **Блок результата** (тест, экзамен, пройденный урок): `Mascot` → `Heading` по центру (балл или итог) → ряд `Badge` с главными фактами (уровень, балл по шкале, верные ответы, время) → `ProgressBar` без подписей → пояснение текстом, если нужно → строки `ListItem` с подробностями. Факт из бейджа в строках не повторяют. На десктопе `ProgressBar` шириной 400.
- **Закрытый следующий шаг в ленте** (интерактивное видео): строка `ListItem` `State=Disabled` с Bold-замком, название шага и условие. `Alert` здесь не ставят.
- **`ChatButton` на десктопе перекрывает контент** (решение владельца 16.11): поле справа под кнопку не добавляют, ширину колонок не меняют.
