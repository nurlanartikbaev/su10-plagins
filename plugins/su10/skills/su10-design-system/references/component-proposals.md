# Предложения к компонентам

Справочник скилла `su10-design-system`. **Когда открывать:** задачу нельзя собрать без изменения компонента, готовишь блок «Предложения к компонентам» в отчёте, разбираешь очередь.

Это одна очередь на всю команду. Основание — железное правило 17: новых состояний компонентам в ходе задачи не придумывают, а предлагают изменение.

## Как устроена очередь

- **Кто пишет.** Любой, кто нашёл нехватку в ходе задачи: дизайнер или агент.
- **Кто разбирает.** Владелец смотрит очередь раз в неделю и ставит статус.
- **Кто меняет мастера.** Только владелец. Строка в очереди не разрешает править мастер (правила 8 и 17).
- **Пока предложение ждёт.** Работа не стоит: в макете остаётся временное решение с подписью «Нужно в SU10: …» (правило 17).

## Как добавить предложение

1. Проверь таблицу. То же предложение уже есть — допиши свои экраны в его строку, новую не заводи.
2. Добавь строку снизу, статус `Новое`. Одна строка — одно изменение компонента.
3. Повтори предложение в блоке «Предложения к компонентам» своего отчёта. Блок есть в каждом отчёте, даже пустой (правило 17).

| Поле | Что написать |
|---|---|
| Компонент | имя набора и страница в SU10 |
| Что добавить | новое значение варианта, булево свойство, слот или токен, с именем |
| Зачем | какой сценарий без этого не собрать |
| Экраны | ссылки на экраны или id узлов |
| Что стоит временно | что сейчас в макете вместо этого |
| Автор | кто предложил |
| Дата | когда добавлено, `ДД.ММ.ГГГГ` |
| Статус | `Новое`, `Принято`, `Отклонено` или `Сделано` |

## Статусы

| Статус | Что значит | Кто ставит |
|---|---|---|
| `Новое` | ждёт разбора | автор |
| `Принято` | владелец согласен, мастер ещё не изменён | владелец |
| `Отклонено` | менять не будут: причину дописывают в поле «Статус», макет собирают иначе | владелец |
| `Сделано` | мастер изменён и опубликован: временное решение в макетах заменяют | владелец |
