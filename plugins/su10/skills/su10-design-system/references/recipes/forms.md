# Рецепты: формы

Справочник скилла `su10-design-system`. Все рецепты: `recipes/INDEX.md`.

## Рецепты сборки

**Форма.** Вертикальный автолейаут, шаг между полями `Space-16`, между группами `Space-32`. Все поля одного размера. Ошибки — `State=Error` у поля плюс текст в `Show Description`, не отдельным Alert.

**Рецепты без своего компонента** (решения владельца 16.11):
- **Запись голоса** собирают из готовых: `Button` Secondary «Начать запись» → во время записи `Button` `Signal=Error` «Остановить · 02:14» и `ProgressBar` → готовая запись строкой `FileItem` с `Show Remove` и `Button` Tertiary «Записать заново». Своего `AudioRecorder` нет. Иконки: `Video, Audio, Sound / Microphone`, `Call / Record Square`.

## Новые рецепты

Собраны только из компонентов SU10. Строки в примерах — образец тона, текст задаёт задача.

**Длинная форма.** *Новый рецепт, ждёт подтверждения владельца.* Форму, которая не помещается на один экран, делят на 2–6 шагов.
- **`Stepper`** стоит над полями: `CurrentStep` — текущий шаг, лишние шаги выключают свойствами `Step 3`–`Step 6`.
- **Колонка.** На десктопе весь сценарий стоит в центральной колонке 920: ширина от шага к шагу не меняется. Поля собирают по рецепту «Форма» в `Island` с `Show Border`.
- **Кнопки.** На десктопе `Action Panel` последним блоком колонки: `Elevate=Off`, а если шаг длиннее экрана, то `Elevate=On`. «Назад» — `Show Left Button`, на первом шаге выключена. Основная кнопка «Далее», на последнем шаге «Отправить». На телефоне `MobileBottomBar v2` с `Show TabBar=false`.
- **Ошибки на шаге.** «Далее» проверяет только текущий шаг. Если есть ошибка, шаг не меняется: у поля `State=Error` и текст в `Show Description`, фокус на первом поле с ошибкой. Отдельный `Alert` не ставят.
- **Ошибка на прошлом шаге** (ответ сервера после «Отправить»): открывают шаг с ошибкой, у поля `State=Error`, `Toast` `Signal=Error` «Исправьте ошибку на шаге 2». У `Step` только `State` Previous / Current / Next: красный шаг не рисуют.
- «Назад» не проверяет шаг и не стирает введённое.

**Поля в две колонки.** *Новый рецепт, ждёт подтверждения владельца.* Два коротких связанных поля в одном ряду: имя и фамилия, дата и время.
- **Ряд** — горизонтальный автолейаут на `FILL`, шаг `Space-16`. Оба поля на `FILL` и одного размера.
- **Телефон.** Поля идут в одну колонку с шагом `Space-16`.

**Кнопка рядом с полем.** *Новый рецепт, ждёт подтверждения владельца.* Поле с лейблом и кнопка, которая работает с его значением: промокод, код из СМС.
- **Ряд** — горизонтальный автолейаут на `FILL`, шаг `Space-8`, `counterAxisAlignItems = 'MAX'`: низ кнопки совпадает с низом поля ввода. Поле на `FILL`, кнопка на `HUG`, оба `Size=M`.
- **Поле без описания:** `Show Description=false`. С описанием низ ряда опускается на 18 px, и кнопка встаёт ниже поля ввода.
- **Ошибка.** У поля `State=Error`, текст ошибки стоит отдельной строкой под рядом: `Caption 1`, `text/critical-static`, шаг `Space-4`.

**Кнопка отправки формы на один экран.** *Новый рецепт, ждёт подтверждения владельца.* Форма помещается на экран целиком, шагов нет.
- **Десктоп.** Одна `Button` `Weight=Primary`, `Size=M` последним блоком формы: шаг от полей `Space-32`, ширина по подписи, левый край по полям. `Action Panel` здесь не ставят.
- **Телефон.** Кнопка в `MobileBottomBar v2` с `Show TabBar=false`.
- **Подпись** — глагол: «Отправить», «Сохранить».
- **Проверка.** Кнопка активна всегда. Нажатие проверяет поля: у поля с ошибкой `State=Error` и текст в `Show Description`, фокус на первом таком поле.
- **В `Dialog`, `DesktopDrawer` и `MobileBottomSheet`** кнопка стоит в подвале панели, отдельную в форму не кладут.
