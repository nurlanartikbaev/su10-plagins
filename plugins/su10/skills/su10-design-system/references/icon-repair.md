# Ремонт: иконки, обновление библиотеки, массовые правки

Справочник скилла `su10-design-system`. Здесь разовые аварийные процедуры — их запускают,
когда что-то **уже** сломано или когда предстоит трогать много мастер-компонентов сразу.
Для обычной сборки макета этот файл не нужен: подбор и подмена иконок описаны в основном
файле, аудит перед сдачей — в `audit.md`.

Когда сюда идут:

- в уже собранных макетах иконки не того цвета (чёрные вместо токена, белые на белом) —
  раздел «Починка иконок в уже собранных макетах»;
- в компонентах дски лежат устаревшие версии иконок из пака — раздел «Обновление
  библиотеки»;
- предстоит проход, который тронет больше десятка мастер-компонентов — раздел «Массовая
  правка в DS-файле», прочитать **до** запуска.

Общее правило всех трёх процедур: **счётчикам не верить, смотреть глазами.** Скриптовый
проход по 667 иконкам однажды отрапортовал «восстановлено 80, потеряно 0», а на деле снёс
контекстные токены цвета у 134 иконок из 136 в `Button` — файл откатывали через историю
версий. Поэтому каждая процедура заканчивается скриншотом, а не отчётом скрипта.

### Обновление библиотеки — только через интерфейс, не скриптом

Когда в компонентах дски лежат устаревшие версии иконок (вектор зовётся ровно `Vector (Stroke)`
вместо `Vector` **внутри инстанса из пака**, из-за чего подмена теряет цвет), **править это скриптом нельзя**. Штатный
путь — в DS-файле принять обновления библиотеки: Assets → Libraries → Updates → Update all,
затем опубликовать DS. Figma при этом переносит оверрайды корректно.

**Проверено на практике, чем кончается скриптовый путь.** Проход по 667 вложенным иконкам
с `swapComponent(freshImported)` действительно обновил версию — и снёс контекстные токены
цвета: в `Button` 134 иконки из 136 получили дефолтный `icon/primary` вместо
`icon/white-static` и `*-outline-static`, в `Text Button` — 46 из 48. Файл пришлось
откатывать через историю версий. Скрипт при этом отрапортовал «восстановлено 80, потеряно
0», то есть **счётчикам верить было нельзя**.

### Массовая правка в DS-файле

Перед любым проходом, который трогает больше десятка мастер-компонентов: предупредить
владельца, что страховка — история версий Figma, и назвать время начала правки. Это
единственный способ вернуть оригинальные токены: реконструкция «по подписи» достраивает
`Only Icon=Yes` и состояния Hover/Pressed/Disabled догадками.

### Порядок групп токенов компонентов — по алфавиту

Группы `color/component/<имя>/` в коллекции `Theme` стоят по алфавиту (решение владельца
21.10.2026, первый раз разложено тогда же: 35 групп, 263 токена). Порядок в панели — это
порядок создания переменных, а Plugin API переставлять их не умеет. Значит, держать порядок
можно только **пересозданием**: группы, которые должны идти после новой, создают заново в
конец, перепривязывают к ним все слои и удаляют старые. Токены компонентов скрыты из
публикации, поэтому продуктовые файлы к ним не привязаны и смена id и ключей им не вредит.
Но id и ключи меняются: после прогона обнови их в `keys.md` и в `SKILL.md`, если они там названы.

**Проверка** — запускать после любой правки токенов компонентов:
```js
const col = (await figma.variables.getLocalVariableCollectionsAsync()).find(c => c.name === 'Theme');
const groups = [];
for (const id of col.variableIds) {
  const n = (await figma.variables.getVariableByIdAsync(id)).name;
  if (n.startsWith('color/component/')) { const g = n.split('/')[2]; if (!groups.includes(g)) groups.push(g); }
}
const sorted = [...groups].sort((a, b) => a.localeCompare(b, 'en'));
const k = groups.findIndex((g, i) => g !== sorted[i]);      // -1 — порядок в норме
return k < 0 ? 'ok' : { recreate: sorted.slice(k) };        // эти группы пересоздать, в этом порядке
```

**Пересоздание** — четыре шага, каждый отдельным вызовом (весь файл в один вызов не влезает):

1. **Создать копии.** Старым переменным групп из `recreate` дать имя `zz-old/…`, новые создать с
   прежними именами в порядке `recreate`; скопировать `description`, `scopes`,
   `hiddenFromPublishing`, `codeSyntax` и значения всех мод. Алиасы, которые указывали на старые
   переменные (в том числе у других переменных), переписать на новые. Карту `старый id → новый`
   сохранить: `figma.root.setSharedPluginData('su10ds', 'varRemap', JSON.stringify(map))` —
   обычный `setPluginData` в этом рантайме не работает.
2. **Перепривязать слои** страница за страницей, пачками по 15–20 страниц, `sandbox` отдельно:
   `fills`, `strokes`, `effects`, цвет у участков текста (`getStyledTextSegments(['fills'])`).
   **Слой внутри инстанса** (id начинается с `I`) трогают, только если поле есть в его
   `overriddenFields` (собрать по `instance.overrides` всех инстансов страницы). Иначе слой
   получит лишнее переопределение и перестанет следовать мастеру; унаследованная привязка
   переключится сама, когда перепривязан мастер.
3. **Дочистить и проверить.** Пройти весь файл и найти узлы, у которых в `boundVariables`
   остался старый id. Обычно это **градиенты**: привязка там живёт на точках
   (`gradientStops[i].boundVariables.color`), а не на заливке, и `setBoundVariableForPaint` её не
   видит. Точки пересобирают: `{...stop, boundVariables: {color: {type: 'VARIABLE_ALIAS', id: новый}}}`.
   То же проверить в локальных стилях заливки (`BackgroundTop`, `BackgroundBot`).
4. **Удалить старые** `zz-old/*` — только когда проверка из шага 3 вернула ноль по всем
   страницам и стилям. Потом снова запустить проверку порядка и посмотреть скриншотом пару
   мастеров (`Button`, тот компонент, чьи токены трогали): цвета должны остаться на месте.

Страховка — история версий Figma: перед прогоном назвать владельцу время начала.

### Починка иконок в уже собранных макетах

Инстансы, созданные до обновления библиотеки, **не подхватывают правку сами** — они держат
старую копию с сырым `#212121`. После публикации библиотеки их надо перепривязать.

Эталонный токен берётся **с чистого инстанса того же варианта**, а не угадывается:

```js
async function refIconVar(mainComp, host) {          // host — фрейм экрана: там нужный режим темы
  const tmp = mainComp.createInstance();
  host.appendChild(tmp);
  const ic = tmp.findAll(n => n.type === 'INSTANCE' && /^(Outline|Linear|Bold) \//.test(n.name))[0];
  const v  = ic && ic.findAll(n => n.type === 'VECTOR' && Array.isArray(n.fills) && n.fills.length)[0];
  const f  = v && v.fills[0];
  const id = f && f.boundVariables && f.boundVariables.color ? f.boundVariables.color.id : null;
  tmp.remove();
  return id;
}
```

**Не бери цвет «у соседнего текста».** Выглядит разумно и работает для кнопки с подписью,
но на `Only Icon=Yes` подписи нет, эвристика уползает вверх до первого попавшегося текста
и приносит чужой токен. Реальный случай: кнопка-корзина в карточке каталога получила
`text/primary`, который в Dark-теме белый, — и стала белой на светлой карточке, то есть
исчезла. Правильный токен у неё `icon/info-outline-static`, и чистый инстанс отдаёт его
сразу. Временный инстанс обязательно класть **внутрь целевого фрейма**: вне его действует
другой режим темы и токен резолвится не в тот цвет.

**Linear-иконки красятся обводкой, а не заливкой.** У штатных исключений (`Sort random` в
`TableHeaderCell`, семейство `Check`) вектора имеют **пустой `fills` и токен на `strokes``.
Версия `swapIcons` выше смотрит только на `fills` и такую иконку просто пропустит. Если
работаешь с Linear-исключением, снимай и возвращай обе привязки:

```js
const painted = ic => ic.findAll(n => n.type === 'VECTOR' &&
  ((Array.isArray(n.fills) && n.fills.length) || (Array.isArray(n.strokes) && n.strokes.length)));
// снять: { fill: f.boundVariables?.color?.id, stroke: s.boundVariables?.color?.id }
// вернуть: setBoundVariableForPaint отдельно в v.fills и в v.strokes
```

Симптом, если пропустить: иконка выглядит чёрной (`#212121` сырым значением в `fills`),
хотя `strokes` вроде бы привязаны — видимый цвет даёт та кисть, которой иконка реально
нарисована.

Слой иконки внутри инстанса **не подменяется через `swapComponent` и не скрывается через
`.visible`** — только `setProperties` на родителе, иначе инстанс уходит в сломанное
состояние (`resetOverrides()` чинит).

**Три вещи, на которых легко потерять время:**
1. **Ключи берутся пачкой за один вызов.** `Figma:search_design_system` отдаёт один запрос
   за вызов; вместо него — один `use_figma` с fileKey пака `SY8WplV9pQCSFLWfD1pTcQ`
   (единственная рабочая страница — `Pack`), возвращающий ключи сразу для всего списка:

   ```js
   const want = ['Essentional, UI / Trash Bin Minimalistic', 'Arrows / Alt Arrow Right'];
   const norm = s => s.replace(/\s+/g, ' ').trim().toLowerCase();
   const map = {};
   for (const c of figma.currentPage.findAllWithCriteria({ types: ['COMPONENT'] })) {
     if (!/^Outline/.test(c.name)) continue;
     const n = norm(c.name.replace(/^Outline\s*\//i, ''));
     if (want.some(w => norm(w) === n)) map[c.name] = c.key;
   }
   return map;
   ```
2. **Имена сопоставлять только нормализованно.** У части иконок хвостовой пробел
   (`"Home "`, `"Bell "`, `"Phone "`), у категории Letter — двойные пробелы вокруг слэша.
   Строгое равенство промахивается: `s.replace(/\s+/g,' ').trim().toLowerCase()`.
3. **Описания в паке заполнены по-русски** (`Базовый UI · Home · главная · Outline — …`),
   поэтому в панели ассетов ищется «корзина», «стрелка», «замок» — и сразу видно, какой
   стиль брать.

**Брендовые лого.** Telegram и WhatsApp в паке есть, но **только в стиле Bold** — это
законное исключение из правила «только Outline», логотип не перерисовывается под обводку.
Instagram, TikTok, VK, YouTube в паке нет: переносятся из исходного макета клоном.
