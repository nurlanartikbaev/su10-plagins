# Гайд для команды: путь макета по шагам

Справочник скилла `su10-design-system`. Источник: «JUZ40: гайд по генерации дизайна», 18.11.2026.
Гайд для всех, кто генерирует дизайн: дизайнеров, фронтенд- и бэкенд-разработчиков.

**Когда открывать:** человек спрашивает, с чего начать, как установить плагин, что делать дальше,
как сформулировать запрос; нужен текст подсказки, частая ошибка или чек-лист перед передачей.
Короткая карта шагов для блока «Дальше» лежит в `SKILL.md`, раздел «Как отвечать».

Человек ставит задачу и принимает решения. Claude собирает и проверяет экран.

## Подготовка

Один раз:

1. Открыть Claude Code и добавить маркетплейс: `/plugin marketplace add nurlanartikbaev/su10-plagins`
2. Установить плагин: `/plugin install su10@su10-plugins`
3. Подключить Figma к Claude Code и войти в свой аккаунт
4. Найти свой личный файл в проекте **JUZ40 Workspace**. Черновики живут только там

Скилл запускается сам, когда просят собрать экран в SU10.

Правила часто меняются. Перед новой задачей обновить скилл:

```
/plugin marketplace update su10-plugins
/plugin update su10@su10-plugins
```

## Термины

| Термин | Что значит |
|---|---|
| Апрув | Явное подтверждение продакта фичи, что экран принят |
| Хэндофф | Передача готовых экранов в разработку |
| Чистовой файл | Файл Figma, из которого разработка берёт экраны |
| Инстанс | Копия компонента SU10 на макете |
| Детач | Отвязка инстанса от компонента. Так делать нельзя |
| Автолейаут | Автоматическая раскладка элементов во фрейме Figma |

## 8 шагов

На каждом шаге решение принимает человек: что оставить, что исправить, что передать дальше.
Хэндофф начинается только после апрува.

```
1. Контекст → 2. Варианты → 3. Выбор → 4. Правки → 5. Состояния → 6. Проверка → 7. Хэндофф → 8. Чистовой файл
               ↑ нужны ещё варианты ┘    ↑ есть находки после проверки ──────┘
```

| Шаг | Что делает человек | Что написать |
|---|---|---|
| 1. Контекст | Прикрепляет спеку или ссылку на Confluence, Jira, Figma. Называет роль и платформу. Сразу отвечает на вопросы, без которых меняется устройство экрана. Вопросы по спеке решает её автор | Вот спека: <ссылка>. Роль: ученик. Платформы: телефон и десктоп. Разбери требования, задай вопросы и покажи карту экранов |
| 2. Варианты | Просит 3–4 решения сразу. Хорошие варианты различаются устройством экрана, а не цветом кнопки | Собери 3 разных варианта экрана. Подпиши каждый кодом и напиши, в чём его идея |
| 3. Выбор | Выбирает по коду. Остальные варианты не удаляет, пока не выбран финальный: их удобно сравнивать | Берём А2. Сделай от него ещё 3 варианта |
| 4. Правки | Называет экран, что мешает и какой результат нужен. Крупную правку сначала смотрит на копии | В А10 · Путь построен длинный подзаголовок в тосте. Оставь только главное. Покажи правку копией рядом с исходным экраном. Оригинал не меняй |
| 5. Состояния | Собирает весь сценарий. Один удачный экран ещё не готов к разработке | Берём А2. Собери состояния и сценарии: загрузка, ошибка, пусто, длинный текст. Добавь десктоп |
| 6. Проверка | Claude прогоняет аудит, матрицу состояний и проверку доступности. Затем человек смотрит экраны сам: у скрипта есть слепые зоны | Прогони аудит, проверь состояния и доступность. Покажи снимки в тёмной и светлой теме |
| 7. Хэндофф | Получает явный апрув продакта фичи: код экрана в чате, комментарии или задаче. Затем просит хэндофф и читает ревью | Подготовь к хэндоффу |
| 8. Чистовой файл | Переносит секции руками по списку ниже | Делает сам |

### Шаг 7: хэндофф

На доску попадают только апрувнутые экраны. Апрув даёт продакт фичи: человек из поля «От кого»
в `TaskPassport`. Nurla подключается только в спорных случаях и когда нужен компонент.

Claude запускает критиков, проверяет состояния и сверяет макет с кодом. Все правки идут на копиях,
оригиналы не меняются. Результат: доска сценариев на русском и казахском и отдельная секция ревью.
Подробно: `handoff.md`.

Секция готова к разработке, когда:

- в ревью нет открытых пунктов «Блокирует»;
- у каждого расхождения с кодом есть решение и исполнитель;
- чек-лист ниже закрыт.

### Шаг 8: перенос в чистовой файл

Этот шаг человек делает сам. Подробно: `team-workflow.md`, §5.

1. Открыть проект роли: Student, Parent, Curator или Admin
2. Открыть файл `<Раздел> (<Роль>)`. Файла нет: создать, попросить дизайнера сделать обложку и сообщить команде
3. Создать страницу `<Фича> [<Месяц апрува> <Год>]` и поставить её самой верхней
4. Вставить русскую и казахскую секции целиком. Есть секция `Фронт и мобилка: различия`: перенести и её
5. Оставить секцию ревью в личном файле. Открытые пункты записать в задачу
6. Проверить после вставки число экранов, связи с SU10, темы и стрелки
7. Поставить Ready for development на готовые секции и приложить ссылку к задаче

## После передачи

**Design QA.** Когда фича свёрстана, сверить стенд с макетом. Дефект записать в задачу разработчика:
код экрана, снимок стенда и снимок макета. После правки проверить экран ещё раз.
Фраза: `Сверь стенд с макетом: <адрес стенда>. Покажи расхождения по кодам экранов`

**Доработка.** Секцию в чистовом файле не править. Снять Ready for development, исправить копию в
личном файле и сохранить старые коды экранов. Затем снова подготовить изменённые экраны к хэндоффу,
перенести их и написать в задаче, что изменилось. Подробно: `team-workflow.md`, §5.7.

## Подсказки

Точный запрос экономит итерации.

| Ситуация | Что написать |
|---|---|
| Решение непонятно | Почему ты взял `State=Pressed` в этой кнопке? |
| Варианты похожи | Варианты слишком похожи. Сделай решения с другим устройством экрана |
| Нужно сравнить правки | Собери правки в одной секции: слева как было, справа новое, рядом текст о том, что изменилось |
| Экран исправлен руками | В В3 я собрал карточку в 3 строки. Сделай так же на всех экранах |
| Нет подходящего компонента | Какие компоненты SU10 закрывают эту задачу? Если таких нет, предложи изменение |
| Текст длинный | Сократи тексты по правилу 15 |
| Блоки повторяют друг друга | Найди тавтологии на экране и предложи, как упростить |
| Нужен свежий взгляд | Пройдись критиком по этим экранам |
| Понять заранее, что фронт соберёт без доработок | Сверь макет с кодом. Покажи, что фронт соберёт как есть, а что нужно обсудить |

Не хватает решения или компонента:

- решение спорное: написать Nurla и приложить ссылку на макет;
- у компонента нет нужного состояния: попросить Claude добавить предложение в `component-proposals.md`;
- элемента нет в SU10: попросить собрать локальный компонент в личном файле и сообщить Nurla.

Новое правило или ошибка в скилле: написать Nurla, что просили, что получилось и чего ждали.
Приложить снимок макета.

## Частые ошибки

Эти ошибки уже встречались в макетах SU10. Их ищут первыми.

| Ошибка | Как правильно |
|---|---|
| Кнопка стоит в `State=Pressed` | `State=Rest`. Для видимой плашки `Weight=Secondary` |
| Линия под последней строкой списка | Выключить `Show Divider` у последней строки |
| Текст прилипает к обводке | Минимум `Space-4` с каждой стороны |
| Один факт повторяется в нескольких блоках | Оставить его в одном месте |
| Шторка не доходит до низа экрана | Прибить шторку к низу автолейаутом |
| Кнопка отправки стоит рядом с полем | Поставить кнопку внутрь поля |
| Недоступный блок приглушён и закрыт замком | Не показывать блок. На его месте написать в `Alert`, что сделать |
| В пустых состояниях разные маскоты | `Sad`. Для пустого поиска `Search` |
| Пустое состояние есть только на одном экране | Проверить каждый блок с данными по матрице состояний |
| Инстанс детачнут или перекрашен | Предложить изменение компонента. На макете подписать «Нужно в SU10: …» |
| Текст на «ты», с длинным тире или точкой в конце строки | На «вы», без длинного тире и без точки в конце |

## Чек-лист перед передачей

Каждый пункт закрывают до Ready for development.

- [ ] Экраны собраны из компонентов SU10, детачей нет
- [ ] Цвета, отступы и радиусы стоят на переменных, текст на стилях
- [ ] На экране одна Primary-кнопка
- [ ] Компоненты стоят в `State=Rest`
- [ ] Аудит пройден, находки исправлены
- [ ] Состояния и доступность проверены
- [ ] Экраны проверены в тёмной и светлой теме
- [ ] Экраны проверены на телефоне и десктопе, если задача для обеих платформ
- [ ] Тексты помещаются на русском и казахском
- [ ] На доске только апрувнутые экраны
- [ ] Пункты «Блокирует» в ревью закрыты, у расхождений с кодом есть решение и исполнитель
- [ ] Страница фичи стоит самой верхней в чистовом файле, проверка после вставки пройдена
